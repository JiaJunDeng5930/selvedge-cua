Run the body of an async JavaScript function. Use `await` for native calls and `return` a JSON-serializable result. A run has a 60-second limit and allows up to 32 active native calls. Desktop changes follow script call order. Reads can run alongside input, so await a change before reading its result.

## Window observation and input

- `listWindows({bundleId})` or `listWindows({pid})` returns `{windows}`. Each window has `{windowId,pid,title,bounds,onScreen}`. `bounds` is the array `[x,y,width,height]` in desktop points. `title` may be null or empty. An `onScreen:false` window is unavailable to pointer, scroll and window capture. An on-screen window can be behind another window.
- `readUI({pid?,windowId?,maxDepth?,maxNodes?,fields?})` returns `{pid,window,focused,truncated,windowInput,atMs,input}`. Select by PID or window ID, or omit both to read the foreground app. `window` and `focused` may be null. An explicit window ID scopes focus to that window. Use `windowInput.windowId` for input when `windowInput.status === "ready"`. Other statuses are `unmatched`, `ambiguous` and `unavailable`. An `unavailable` response includes the requested `windowId`.
- `observeScreen({target?,durationMs?,intervalMs?,imageBudget?,maxDimension?,preserveInputBoundaries?})` captures the main display by default. `target` is one of `{windowId}`, `{displayId}` or `{region:{x,y,width,height}}`. Window capture isolates the target window. Display and region captures include occluding windows. In Locked Use, supply `{windowId}`. `durationMs` is 0–30000 and defaults to 0 (one frame). `intervalMs` is 16–30000 and defaults to 100. The effective interval can grow to fit at most 24 samples. `imageBudget` is 1–12 (default 6). `maxDimension` is a positive integer that caps the longest side of each sampled viewport in pixels without upscaling. Set `preserveInputBoundaries:true` to distinguish equivalent frames observed after different completed input dispatches. `obs.started` resolves to `{atMs}` after the first capture. `await obs` and `await obs.finished` return the same manifest.
- `pointer({windowId?,position?,durationMs?,intervalMs?,buttons?,hold?,operation?})` calls the synchronous `position(tMs)` before dispatch for each trajectory sample. Return a finite `{x,y}` object. A new trajectory requires `windowId`. Its starting point must be inside the target window unless continuing a held drag. `durationMs` is 0–30000 (default 0), `intervalMs` is 4–30000 (default 16), and the trajectory includes the endpoint with at most 1024 samples. `buttons` defaults to `[]` and accepts codes 0–31, with 0 left, 1 right and 2 middle. Supplying buttons requires `position`.
- `keyboard({pid?,events?,hold?,operation?})` requires a target `pid` when starting a key sequence. `events` defaults to `[]` and contains `{atMs?,key,down}`. Use physical key codes such as `KeyA`, `ShiftLeft`, `MetaLeft` and `ArrowDown`. Set `down:true` for a press and `false` for release.
- `scroll({windowId?,x,y,events,operation?})` requires a window ID or a window-bound operation and a point within that window. Supply 1–1024 `{atMs?,dx?,dy?}` events. Deltas are signed integer pixels and default to 0. Positive deltas scroll right and down. A supplied operation preserves held controls.
- `insertText({target,text})` uses a live `readUI` target for the focused editable control. Prefer this for plain text. Returns `{pid,delivery,sentAtMs}`. `delivery` is `accessibilitySelection` for an element-directed replacement, `focusedProcess` for process-directed text or `noOp` for empty text. Process delivery is resolved against the app's focus when it receives the event.
- `performUIAction({target,action,value?})` takes a live target from `readUI` or `desktop.readMenuBar`. Use an action listed on that node. `AXSetValue` takes a JSON string, number or boolean on a writable element. Returns `{result:{pid,target,action},sentAtMs}`. An app can change window order or focus when handling input or an AX action.

Coordinates are global logical desktop points from the top-left of the main display. Keyboard and scroll event offsets default to zero, must be nondecreasing and must be 0–30000 ms. Keyboard sequences have at most 1024 events. Fields ending in `AtMs` and `atMs` in observations and UI reads use the server's monotonic clock.

`pointer`, `keyboard` and `scroll` return `events` with `{scheduledMs,sentAtMs}`, plus `releases`, `held`, `operation` and the dispatch time bounds. Set `hold:true` on pointer or keyboard to keep controls down. Pass the returned operation reference to continue it, even in a later `run` on the same MCP process. `pointer({operation})` releases held controls in place. A failed run releases its held controls. A rejection after dispatch begins includes a partial receipt. Receipts report event posting. Verify the app's response with a read or capture. Window routing errors have a code on the JavaScript exception and in `structuredContent.code`, such as `windowRequired`, `windowUnavailable`, `windowOwnerChanged` or `windowGeometryChanged`.

### Accessibility trees

`readUI` and `desktop.readMenuBar` use the same traversal options. `maxDepth` is an integer from 0 to 32 (default 6). The root is at depth 0. `maxNodes` is an integer from 1 to 500 (default 120). `readUI.focused` is returned independently of these tree limits. `truncated` signals an incomplete traversal.

Omit `fields` to request all supported attributes, or pass a list drawn from `role`, `subrole`, `title`, `description`, `value`, `position`, `size`, `enabled`, `identifier`, `help`, `placeholder`, `actions` and `settable`. An element always has `role` where exposed and a `target` reference. Tree nodes have `children` arrays. `position` is `{x,y}` and `size` is `{width,height}`. Attributes can be absent when the app does not expose them. `window.windowId` is present when the window is ready for input. References expire after eight newer tree reads, when the application exits, or if the element stops existing.

## Desktop helpers

- `desktop.listApps()` returns `{apps:[{bundleId,name,pids}]}`. It discovers running regular apps and bundled apps in `/Applications`, `/System/Applications` and `~/Applications` including subfolders. An empty `pids` array indicates no running regular instance was observed. The bundle ID can be used for window discovery or launch.
- `desktop.launchApp({bundleId})` or `desktop.launchApp({name})` returns `{bundleId,pid}`. A name must uniquely match a name from `desktop.listApps()`, ignoring ASCII case. A single running instance is reused. Otherwise Launch Services opens the registered app with activation disabled in the request. The app may activate itself. Await `listWindows({pid})` afterward. A launch receipt reports a process, and its window may take longer to appear.
- `desktop.readMenuBar({pid,maxDepth?,maxNodes?,fields?})` returns `{pid,menuBar,truncated}`. It reads the application's AX menu bar without opening menus. `menuBar` is null when the app exposes none. Some apps populate submenus only after opening them. Menu targets work with `performUIAction` when they advertise the required action.
- `desktop.selectText({target,text,prefix?,suffix?,selectionType?})` uses a live target exposing a string AX value and a writable `AXSelectedTextRange`. `text` must be nonempty and match exactly once, with optional immediately adjacent `prefix` and `suffix`. `selectionType` is `range` (default), `cursorBefore` or `cursorAfter`. Returns `{pid,target,range:{location,length}}` with offsets and length in UTF-16 code units.
- `desktop.paste({target,text,format?,plainText?})` posts Command-V after checking the target is the app's focused editable control. `format` is `text` (default) or `html`. `plainText` supplies an optional plain-text representation for `html`. The operation temporarily writes to this Mac's system clipboard and restores the previous items after a short delivery window. If the clipboard changes meanwhile, the newer contents are preserved and `clipboardRestored` is false. Returns `{pid,clipboardRestored}` after sending the shortcut. Verify the paste result in the target app.

## MCP result and PNGs

The returned value is `structuredContent.result`. Successful captures appear under `structuredContent.observations`, with `imageOffset` and `imageCount` indexing the PNG attachments. Add a tile's `imageIndex` to `imageOffset` to choose the attachment. `imageRect` is in PNG pixels and `desktopRect` is in desktop points. The manifest's `viewport` points to the last real frame. `frames` lists equivalent capture intervals and their sample counts. The image budget can pack several views or aligned scroll strips into one PNG. The capture rejects if required detail cannot fit the budget. An uncaught error appears in `structuredContent.error`.
